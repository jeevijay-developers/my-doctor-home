# AI Blog Markdown Rendering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert AI-generated Markdown, including collapsed one-line Markdown, into safe formatted HTML in the Admin editor and public blog.

**Architecture:** Add one shared `markdownToHtml(content)` utility that preserves existing HTML, normalizes recognizable Markdown block boundaries, parses Markdown with `marked`, and sanitizes with `DOMPurify`. Convert AI output before TipTap receives it and use the same utility for public compatibility with older Markdown posts.

**Tech Stack:** React, TypeScript, TipTap, `marked`, `DOMPurify`, Vitest, Testing Library.

## Global Constraints

- Existing HTML/manual posts pass through unchanged.
- AI output is sanitized before rendering or editor insertion.
- Headings, bold text, ordered/unordered lists, paragraphs, and horizontal rules render as HTML.
- Collapsed Markdown markers are separated only when they match recognizable block constructs.
- The public page remains backward-compatible with stored Markdown.

- [ ] **Step 4: Implement normalization and conversion**

Implement `markdownToHtml` with this order:

```ts
if (!content) return "";
if (/<\\/?[a-z][\\s\\S]*>/i.test(content)) return DOMPurify.sanitize(content);
const normalized = normalizeMarkdownBlocks(content);
return DOMPurify.sanitize(marked.parse(normalized) as string);
```

`normalizeMarkdownBlocks` must insert newlines before heading markers, ordered/bulleted list markers, and standalone horizontal rules when they appear after text, while preserving ordinary hashes, asterisks, and hyphens. Escape or sanitize parser output through `DOMPurify` before returning it.
