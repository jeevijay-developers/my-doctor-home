# Multi-doctor clinics — Phase 3 (money) + doctor-aware content + release

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or executing-plans. Checkbox steps.

**Goal:** Finish the multi-doctor spec: (1) owners can buy extra doctor seats themselves, (2) per-doctor revenue reports and an opt-in "my earnings" view for doctor logins, (3) services, reviews, blog authors and the directory become doctor-aware, (4) the launch switch and seat price are controllable from the superadmin UI, (5) release.

## Decisions

1. **Seats are dated periods, not a counter.** New table `clinic_seat_periods`; `clinic_doctor_seat_limit()` = 1 + superadmin-granted `clinic_doctor_seats.extra_seats` + Σ quantity of periods active NOW (+ trial seats), capped by `doctor_seat_max`. A late/missed cron can never grant free seats; no change to the renewal cron.
2. **One audited money path:** seat orders reuse `plan_upgrade_payments` (+ `kind`) and `apply_plan_upgrade_payment` (locked, idempotent); webhook/verify unchanged.
3. **Premium + active + real `plan_end` only** (no trial, no Pro/Free). Amount is computed in SQL (`seat_order_quote`), never by the client: `ceil(qty × price × 100 × min(days_left,30)/30)` paise, minimum 100 paise. Mid-period add-on period = `[now, plan_end)`. Renewal order may include seats: period = `[renewal start, +30d)` (immediate: `[now, now+30d)`; scheduled: `[plan_end, plan_end+30d)`). Seats are non-refundable (stated in the UI); superadmin can still grant/adjust.
4. **Revenue is computed server-side** from `appointments` + `invoices` with the doctor snapshotted on the invoice (`invoices.practitioner_id`, set by a BEFORE INSERT trigger; `ensure_invoice_for_appointment` is NOT modified). Refunds counted in the month refunded; paid online no-shows are a separate bucket; dates in IST; revenue = ex-GST `amount` (GST shown separately).
5. **"My earnings" is opt-in:** `website_settings.show_doctor_earnings` (default false, owner-only change); doctor logins get aggregate-only numbers for themselves via `get_my_practitioner_revenue`.
6. **Content:** `service_practitioners` (no rows = every doctor offers it), `reviews.practitioner_id`, `blog_posts.practitioner_id` all nullable; `public_booking_price` honours the mapping; reviews insert hole closed; directory returns one row per `directory_listed` practitioner for polyclinics only.
7. **`directory_listed` is honoured** on practitioner pages (noindex) and in the sitemap.
8. **Retention:** `clinical_access_log` rows older than 1 year purged daily by pg_cron.
9. Custom plans do not carry seats (superadmin grants cover it); `billing.own_only` is replaced by the opt-in earnings view.

# Part DB — three migrations, one agent, serial

### Task DB1: Seat periods + seat orders  (`20261127100000_seat_periods.sql`, test `13_seat_periods.sql`)

**Produces (interfaces for later tasks):**
- `plan_upgrade_payments`: `kind text NOT NULL DEFAULT 'plan' CHECK (kind IN ('plan','seats'))`, `seats_quantity int`, `unit_price numeric`, `period_start timestamptz`, `period_end timestamptz`. Seat rows use `from_tier='premium'`, `target_tier='premium'`.
- Table `clinic_seat_periods(id uuid pk, doctor_id uuid → profiles ON DELETE CASCADE, quantity int CHECK >0, starts_at, ends_at (> starts_at), payment_id uuid UNIQUE → plan_upgrade_payments ON DELETE SET NULL, created_at)`; RLS: SELECT for clinic members/admin; no client writes. Index `(doctor_id, ends_at)`.
- `clinic_doctor_seat_limit(_doctor_id)` redefined per Decision 1 (copy live body; keep `clinic_multi_doctor_enabled` gate, trial seats, cap).
- `seat_order_quote(_doctor_id uuid, _qty int) RETURNS jsonb` (SECURITY DEFINER; service_role + authenticated-wrapper): `{ok:true, amount_paise, unit_price, days_left, period_end}` or `{ok:false, error}` with errors `NOT_ENABLED`, `PRICE_NOT_SET`, `PLAN_NOT_ELIGIBLE` (not premium+active+future plan_end, or <1h left), `INVALID_QTY`, `SEAT_MAX` (granted + active purchased + qty > doctor_seat_max − 1). Plus `get_seat_order_quote(_qty int)` for the signed-in owner / staff with `billing.manage` (clinic from caller, never from payload), fail closed.
- `apply_plan_upgrade_payment` (copy LIVE body, same signature): add a `kind='seats'` branch (re-check eligibility + cap inside the lock; insert period `[now, plan_end)`; if the plan lapsed/cancelled or cap exceeded between order and capture → do NOT apply, write `admin_audit_log` `seat_payment_not_applied_*` flagged for manual refund, same style as the suspended-doctor case) and, for `kind='plan'` rows with `seats_quantity > 0`, insert the renewal period (immediate vs scheduled as in Decision 3). Plain plan payments take the exact same path as today when `seats_quantity` is NULL/0. Return jsonb includes `kind` and `seat_limit` for seats.
- `get_clinic_doctor_access` (copy LIVE; keep all current keys) gains `purchased_seats int` (active now), `seats_valid_until timestamptz|null` (earliest end of active periods), `can_buy_seats boolean` (price set AND quote eligible for qty 1).
- `plan_upgrade_payments` readers keep working (SABilling selects named columns).
**Tests (13):** quote maths (proration, ceil, min, cap, errors); stranger/staff-without-permission refused; apply seats → period + limit raises; idempotent re-apply; lapsed plan → not applied + audit; renewal order with seats creates future period and the limit only counts it from `starts_at`; expired period stops counting without any cron; plain plan payment unchanged (existing `plan_flow.sql` passes); `set_clinic_doctor_seats` grants still add on top; clinics keep `seat_limit = 1` when the feature/flag is off.

### Task DB2: Per-doctor revenue  (`20261127100100_practitioner_revenue.sql`, test `14_practitioner_revenue.sql`)
- `invoices.practitioner_id uuid NULL` + FK `(practitioner_id, doctor_id)` is NOT possible with nullable composite on `ON DELETE`—use plain FK to `practitioners(id)`; BEFORE INSERT trigger `trg_a0_invoice_practitioner` fills it from `appointments.practitioner_id` via `NEW.appointment_id` (never overwrites an explicit value); backfill existing invoices from appointments (batched, triggers on invoices disabled only if a trigger would fire side effects—check first); index `(doctor_id, created_at)` and `(doctor_id, practitioner_id, created_at)`.
- `website_settings.show_doctor_earnings boolean NOT NULL DEFAULT false`; owner-only change guard (same pattern as `guard_clinical_visibility`, error `OWNER_ONLY`; also on INSERT).
- `get_practitioner_revenue(_from date, _to date) RETURNS jsonb` — clinic = owner, or staff with `billing.view` (COALESCE fail-closed); refuse NULL/`_from>_to`/range > 366 days → `{ok:false,error:…}`. Output `{ok:true, from, to, rows:[…], unattributed:{…}, totals:{…}}`; each row: `practitioner_id, display_name, is_active, visits_completed` (appointments `status='completed'`, `date` in range), `paid_amount` (invoices `status<>'refunded'`, IST `created_at` in range, ex-GST), `gst_amount`, `by_mode` (`cash|upi|card|online|other|unrecorded`), `refunds_count`, `refunds_amount` (by `refunded_at`), `no_shows`, `paid_no_shows_count/amount` (`status='no_show'` AND `payment_status='paid'`), `platform_charge`, `net` (from invoice snapshot columns). Include inactive doctors that have activity; "unattributed" = invoices with NULL practitioner_id.
- `get_my_practitioner_revenue(_from,_to)` — identity from `staff_members` (role 'doctor', active) or the owner's own practitioner row; practitioner taken from that row, never from parameters; refuse with `NOT_ENABLED` unless `show_doctor_earnings`; return that doctor's row ONLY (no patient names, invoice numbers, UTRs, lists).
**Tests (14):** attribution incl. appointment deleted/reassigned after invoicing (snapshot wins), refund month, paid no-show bucket, cancelled-paid not counted, IST boundary (invoice at 23:30 IST vs UTC), single-doctor clinic returns one row equal to the clinic totals, stranger/doctor-login-without-switch refused, doctor sees only own numbers, owner toggle owner-only, `ensure_invoice_for_appointment` untouched (old suites pass).
